Before step 01

Decisions

What's settled and what's still yours
All settled
  • Workers (WebAssembly), not ContainersSettledIt runs free, scales to zero and has no cold start. cargo bench puts a full puzzle (generate + solve) at about 82 µs natively, or roughly 0.25 ms at a pessimistic 3× for wasm, well inside the free plan's 10 ms of CPU per request. Containers stay as the fallback (see the last card).
  • Port this repo, not sudoku-rust-apiSettledThis repo is already on sudoku 0.8 / rand 0.8 / base64 0.22. The Vercel repo is on rand 0.5 and would need those upgrades first.
  • metrics.nanos removed; timings move to cargo benchSettledstd::time::Instant panics in WebAssembly, and Workers freezes the clock while your code runs, so any timer reads 0. The response now has only metrics.counts. The component's PuzzleApiData type marks nanos optional as of 0.1.340, and it only ever read puzzle and ref. benches/puzzle.rs (Criterion) times generate, solve and new_puzzle natively. Native times were about 80 µs, 2 µs and 82 µs on 2026-11-10.
  • The page calls its own origin: platform="cloudflare"Settledproto-sudoku-wc 0.1.339 knew only local (http://localhost:8080/api), netlify and vercel, and fell back to Vercel for anything else. 0.1.340 adds cloudflare: '/api' in src/utils/store.ts. The path is relative, so it follows whatever host serves the page, including a custom domain later. The component sends X-Requested-With and X-Custom-Header, so cross-origin callers still rely on the CORS preflight.
  • Keep the pinned CDN version, not @latestSettledThe page keeps loading an exact version from jsDelivr (proto-sudoku-wc@0.1.340), and .wc-loader keeps bumping it. Stencil's entry file lazy-loads hashed chunks through the same URL, and jsDelivr caches @latest per file, so after a release the entry file and chunks can come from different versions and fail to load. A pin also gives a review step, a one-line rollback and a commit history of what was served. If running .wc-loader by hand gets old, automate it rather than unpin.

Step 03 · src/lib.rs

Rewrite the handlers

Replaces src/main.rs
Done

The puzzle logic is the same, minus the timers and the println!. fetch adds CORS headers to every response, the router's 404s included, which is what Cors::permissive() did. Delete src/main.rs. You don't need a / route, because Static Assets serves index.html before the Worker runs.

Routes
/api/puzzle · /api/:name · /:name · OPTIONS on any path
Tag
"cloudflare" (was "platform")
use base64::{engine::general_purpose, Engine as _};
use serde_json::json;
use sudoku::Sudoku;
use worker::*;

const PLATFORM: &str = "cloudflare";

fn with_cors(mut resp: Response) -> Result<Response> {
    let h = resp.headers_mut();
    h.set("Access-Control-Allow-Origin", "*")?;
    h.set("Access-Control-Allow-Headers", "*")?;
    h.set("Access-Control-Allow-Methods", "GET,OPTIONS")?;
    Ok(resp)
}

fn greet(name: Option<&String>) -> Result<Response> {
    let name = name.map(String::as_str).unwrap_or("World");
    Response::from_json(&json!({ "hello": name }))
}

fn puzzle() -> Result<Response> {
    let puzzle = format!("{}", Sudoku::generate().to_str_line());
    let blanks = puzzle.matches('.').count();
    let line = Sudoku::from_str_line(&puzzle)
        .ok()
        .and_then(|s| s.solution())
        .map(|s| format!("{}", s))
        .unwrap_or_default();

    let data = json!({
        "metrics": {
            "counts": { "blanks": blanks, "clues": 81 - blanks }
            // No "nanos": Workers freezes the clock while code runs, so they
            // always read 0. benches/puzzle.rs measures them natively instead.
        },
        "puzzle": puzzle,
        "ref": general_purpose::STANDARD.encode(line),
        "tag": PLATFORM
    });
    Response::from_json(&data)
}

#[event(fetch)]
async fn fetch(req: Request, env: Env, _ctx: Context) -> Result<Response> {
    let resp = if req.method() == Method::Options {
        Response::empty()?
    } else {
        Router::new()
            .get("/api/puzzle", |_, _| puzzle())
            .get("/api/:name", |_, ctx| greet(ctx.param("name")))
            .get("/:name", |_, ctx| greet(ctx.param("name")))
            .run(req, env)
            .await?
    };
    // One place for CORS, so 404s from the router get the headers too.
    with_cors(resp)
}

If something breaks

  • "time not implemented on this platform" panic. Something still calls std::time::Instant or SystemTime. Remove it, or use worker::Date::now().
  • getrandom build error mentioning wasm32-unknown-unknown. The js feature is missing, or a second getrandom version crept in. Run cargo tree -i getrandom.
  • Every /api/:name request returns 404. Newer router versions use {name} instead of :name.
  • "/" returns JSON {"hello":"..."} instead of the page. The assets directory is wrong, or run_worker_first is set.
  • Error 1102, CPU limit exceeded. This is unlikely at about 82 µs per puzzle natively, but a debug build is much slower. Make sure the build uses --release.

This keeps main.rs as it is, and the nanosecond timings stay real. You add a multi-stage Dockerfile that copies index.html into the image's working directory, a small TypeScript Worker that forwards requests to the container on port 8080, and a wrangler.jsonc with a containers block. The costs are the $5/month Workers Paid plan and container cold starts.
